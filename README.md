# 酒馆你害我不浅

SillyTavern 前端扩展。四格：世界书、预设、API（钥匙本）、界面。

## 安装和更新

酒馆 → 扩展 → 安装扩展，填入 `https://github.com/zhouyesyes/tavern-ruined-me`。
已安装的在扩展管理中更新，再刷新酒馆，版本 **0.10.4**。

## 世界书面板

扩展面板是「管理」，弹窗是「这个聊天开哪些」，各管各的。任何时候都不会自动弹窗（新开聊天也不弹），想选就点面板里的按钮。

- 面板上半是「这个聊天绑定的」（角色 / 聊天 / 全局三小段，哪段是空的就整段不显示）；下半「所有世界书」是一个大折叠（默认收起），点开才是一本一本的书，每本也默认折叠。面板里没有任何开关，开关只在「这个聊天开哪些」弹窗里。
- 每本书默认折叠，标题旁一行小字：分类几个、开几个/共几个。
- 点开一本：顶上是自定义分组的小标签（点一下可改名——要点「保存」才存——或删除；＋新建），下面所有条目全部列出，按组分段、每段可折叠。每条一行：开/关状态、名字、归类下拉、展开小箭头。
- 点箭头只读显示这条的关键词和正文，不能改（要改去酒馆自带世界书页面）。
- 「这个聊天开哪些」一个按钮一个弹窗：分了类的条目（按组）和没分类的条目，勾一下就走；开关写进当前聊天并**一直写回原书**（稍停一下合并保存）。
- 旧版「整本开关」的书自动改成按条目分类，备份和原有设置接过来。

## 状态同步规则

开关立即写入当前聊天的 `chatMetadata.tavern_ruined_me.slots.world`，调用酒馆的 `saveMetadata()` 保存；原书写入共用串行队列，没变化不保存。世界书配置、分组、首次修改备份和最后核对的原书状态存于扩展设置，不包含其它聊天的选择。

1. 新聊天、第一次升级且尚无原书核对记录时，以酒馆当前实际开关为起点。旧聊天的其它 slots 不动。
2. **切进聊天（含新载入、刷新）：以这个聊天自己存的选择为准**写回原书；原书和上次写入对不上（比如 LoreGovernor 等别的插件动过书）也不当成外部修改、不冲掉聊天的配置。聊天里没有记录的新条目才取当前实际状态。
3. 聊天里原书被改动时（在酒馆自带世界书页面手拨开关、开场白/脚本存书、同一聊天里绑定变化）重新核对：和插件最后写入的状态比，变了的条目记进**当前聊天**（下次进来自动恢复），不动其它聊天。生成前（`WORLDINFO_ENTRIES_LOADED`）只把本聊天的选择套到条目副本上，副本里别人临时改的开关不记进聊天。只处理本面板范围内的书。没有完成聊天载入前，不套用上一窗的选择。
4. 异步读书、排队保存前核对聊天 ID、角色、群组、元数据对象、绑定和切换序号。已发出的保存请求不能撤回，但共用队列保证下一聊天等它结束后重新核对；尚未发出的旧任务丢弃。
5. 只能识别接口中可观察到的状态变化：其它扩展如果重复写入完全相同的值，不能判断它是否有新的意图；多个浏览器同时改同一本原书也没有服务端原子锁。不会声称能识别这些不可观察的情况。

原书首次修改前整本备份（只留第一份，留在扩展设置里）。

原生世界书页面的条目开关和灰显随当前聊天更新，显示「聊天配置 · 会同步到原书」。原生编辑器仍可操作，其实际修改会被下一次核对采用。

## 接口依据

核对 SillyTavern `release` 的公开源码（2026-11-08）：

- [world-info.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)：`selected_world_info`、`world_info.charLore[].extraBooks`、`getCharacterLore`、`WORLDINFO_UPDATED`、`WORLDINFO_SETTINGS_UPDATED`、`WORLDINFO_ENTRIES_LOADED`。
- [utils.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/utils.js)：`getCharaFilename` 去掉头像文件名的最后一个扩展名。
- [st-context.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/st-context.js)：角色/群组/聊天 ID、`chatMetadata` 和 `saveMetadata`。

按要求只列角色绑定和全局绑定；单独的聊天绑定书、用户人设书不会因此额外出现在面板。聊天绑定书名仍参与变更检测，防止换开场白时旧配置抢回状态。

## 预设格（0.6.0）

每个聊天记自己用的聊天补全预设、条目开关和顺序；切聊天时先上锁，换预设、写回开关和顺序都完成后才解锁。「切换到这套」要先真的切成功才改记录，切不过去会提示、记录不动。存档点名字可改名（输入框 + 保存）。

用到的酒馆真实接口（SillyTavern `release` 的 `openai.js` / `PromptManager.js`）：

- `oai_settings.preset_settings_openai`：当前预设名；`openai_setting_names[名字]`：下拉选项值
- 换预设：`#settings_preset_openai` 设值并触发 `change`（等于手点下拉，走酒馆的 `onSettingsPresetChange`），再 `await getPresetApplicationPromise()` 等预设载完（含 `prompt_order`）
- 写回开关和顺序：`promptManager.getPromptOrderForCharacter(promptManager.activeCharacter)` 原地改，`promptManager.render(false)` 刷新预设页，`promptManager.saveServiceSettings()` 存下来（等 `SETTINGS_UPDATED`）
- 记录手动改动：`OAI_PRESET_CHANGED_AFTER`、`SETTINGS_UPDATED` 事件
- 切聊天（0.6.2）：酒馆先换「当前聊天」、过一会儿才发 `CHAT_CHANGED`，中间常有一次 `SETTINGS_UPDATED`。手动改动只记进插件已经进好的那个聊天，聊天刚换、还没处理完时不记，免得把旧聊天的预设记到新聊天名下（0.6.1 及以前就是这样导致切聊天时预设不跟着换）
- 旧一点的酒馆（0.6.1 起）：`openai.js` 整个模块一起导入（`import * as`），按名字取。没有 `openai_setting_names` 就按下拉里显示的预设名找选项；没有 `getPresetApplicationPromise`（1.18 及更早）就等酒馆换完预设内容后发的 `OAI_PRESET_CHANGED_AFTER`（最多 8 秒）。0.6.0 逐个导入这两个名字，旧酒馆少一个就整个插件加载失败、从扩展列表里消失

## API 格：钥匙本（0.7.0）

把「通用钥匙API管理器」的功能自己重写进来（没有照搬它的代码），做好后可以删掉它。这一段做的是：

- 钥匙本：每条记名字、地址、密钥、模型、标签、备注；能搜、复制、编辑、删除。存在 `extensionSettings.tavern_ruined_me_keys`
- 点哪填哪：点进任何插件的地址框或密钥框，框右边出一个小钥匙，点开从下面弹出选单，选一条就把这个框和旁边配对的框一起填好（触发 `input`、`change`，插件能收到）。小钥匙贴在框里右边尽头，页面滚动、键盘弹出时跟着框走，点到别处才收起（0.7.4：以前 iPhone 点进框时页面一滚就把它藏了，所以看不到）。框在弹窗里（`<dialog>`，浏览器最上层，酒馆和很多插件的弹窗都是）时，小钥匙和选单放进那个弹窗里，不然会被盖住（0.7.1）
- 测连接：照酒馆「连接」按钮，`POST /api/backends/chat-completions/status`（`chat_completion_source: openai` + `reverse_proxy` + `proxy_password`），由酒馆服务器去拉 `/models`；通了列出模型，点一下就选上
- 不往酒馆反代列表里加（0.7.4 去掉：她用「自定义（兼容 OpenAI）」来源，酒馆不显示那块）；扫描时还会读一下反代列表

- 扫描（0.7.2）：把酒馆反代列表（`proxies`）和所有插件设置（`extensionSettings`，跳过我们自己的）里存的「地址 + 密钥」找出来，列出来勾选，勾了才收进钥匙本；钥匙本里已经有的（同地址同密钥）标出来不勾。酒馆密钥编号（UUID）、关键词这类不算；0.7.3 起还要带数字、至少 12 位、不是 JSON，全大写带下划线的名字（事件常量）不算，不往网页元素、jQuery 内部数据里钻；没有地址的默认不勾。酒馆 API 页自己存的密钥在服务器 `secrets.json` 里，默认读不到，不扫

还没做（下一段）：改了一条时列出用到它的地方让她勾选要改哪些；外面改了钥匙时提示选「更新钥匙本 / 另存一条 / 先不管」。

## 界面格（0.10.0 起，0.10.3 改版）

把酒馆里不常用的按钮和设置收起来。最初照「砚台 · 界面整理」的功能自己重写（没复制代码），0.10.3 起交互和文字都换成自己的。代码在 `src/tidy.mjs`，设置存在 `extensionSettings.tavern_ruined_me_tidy`。勾上＝收起，三处一样。

- **默认不开**；前五项和总开关、操作按钮一起放进默认折叠的「界面整理」。总开关只控制这五项；「恢复原界面」关闭这五项整理，勾选留着。滑动空白修复、手机正则、页面滑动减负和页面全屏独立控制。
- **顶栏**：勾上的图标收进最右边的 «，点它往左展开（扩展程序也能收）。名字用图标自己的提示字（跟酒馆语言走）
- **选项菜单（☰）/ 扩展菜单（魔法棒）**：勾上的收进最下面一个只有 ⋯ 的折叠，点开字小一号
- 只列现在看得到的；酒馆或主题自己藏着的、只在特定聊天里出现的不列，底下小字说有几个
- **扩展程序页**：排成一列（咱们的面板 → 收起的扩展程序 → 酒馆自带 → 酒馆助手 → 其他插件）；「收起的扩展程序」是一个真的盒子（0.10.4 起把收起的扩展挪进去，咱们的面板也挪到最前面；她那边 TauriTavern + 主题里光靠排序排不动），原地往下展开，展开的缩进、小一号、底色淡；最底下「▴ 收起」；「复制排查信息」排查排序问题
- **用户设置**：UI 主题 / 角色处理 / 杂项 / 聊天/消息处理 / ST脚本设置几段可折，搜索设置时自动展开（名字用酒馆官方中文翻译）
- **滑动空白修复（试验）**：让消息始终参与渲染（`content-visibility: visible`、`contain-intrinsic-size: none`），替换旧的独立图层和布局隔离方案。沿用原开关状态，默认关；长聊天可能增加内存和首次绘制开销，实际改善需在设备上对比。
- **页面全屏**：点击进入 / 退出全屏，优先使用可用的 Tauri 窗口接口，否则使用标准 / WebKit 页面全屏接口；不自动进入。不支持或请求失败时提示。手机状态栏和底部横条是否隐藏由 TT / 系统决定，需要真机验收。
- **手机上的正则**（新配置默认关，已有开关保留）：正则名字太长显示省略号，开关按钮留在同一行，不超出屏幕
- 砚台界面整理还在运行时前五项不生效（防两边打架），独立功能仍可使用
- 关闭总开关后前五项恢复原样（有测试），独立功能保留各自状态

### 页面切换时的插件开销

界面整理的连续更新合并到下一帧；关闭整理时停止监听菜单。用户设置搜索只在开始搜索 / 清空时重新整理。选项菜单按 ID 一次分组，避免重复扫描；识别本插件时只读外层标题。世界书列表的生命周期监听跳过角色、人设等页面的无关更新，提示节点保留复用，列表重建后仍同步。以上减少本插件的额外工作，不代表已验证 TT 真机的滚动帧率；主题模糊、图片和 WebView 自身的开销仍需真机判断。

**页面滑动减负（试验）**：默认关闭，独立开关。为角色、人设、世界书、设置、扩展及共用抽屉 / 弹窗移除背景模糊、盒子阴影和文字阴影，关闭恢复主题样式。不增加滑动监听、不改手势、不隔离图层、不强制预渲染全部图片。依据酒馆公开 [mobile-styles.css](https://github.com/SillyTavern/SillyTavern/blob/release/public/css/mobile-styles.css) 的面板结构；目标是减轻绘制成本，未验证 TT 真机输入延迟改善，需开关对比。
