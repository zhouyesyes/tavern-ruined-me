# 酒馆你害我不浅

SillyTavern 前端扩展。目前提供世界书面板；预设和 API 留作后续功能。

## 安装和更新

酒馆 → 扩展 → 安装扩展，填入 `https://github.com/zhouyesyes/tavern-ruined-me`。
已安装的在扩展管理中更新，再刷新酒馆，版本 **0.3.0**。

## 世界书面板

扩展面板是「管理」，弹窗是「这个聊天开哪些」，各管各的。新建、切换聊天不会弹窗；只有**新开聊天**会弹一次「这个聊天开哪些」。

- 面板默认折叠。展开后看到当前角色主书、额外绑定书、启用的全局书（额外绑定按头像文件名查，不按显示名猜；群聊取成员绑定书的并集）。
- 每本书是一张折叠卡片：顶上一排小标签（全部／常开／常关／各分组／未分类／＋新建），点标签筛选该组；选中自定义组时可改名、删除（删除要确认，条目回未分类）。条目按组列出，没分类的单独一段；每条右边是归类下拉和编辑（名称、关键词、正文，直接改原书）。
- 卡片最底下一行小字：恢复原书、从面板移除（只从面板去掉，原书、分组、备份都留着，可重新显示）。
- 「这个聊天开哪些」一个按钮一个弹窗：只有分了类的条目（按组）和没分类的条目，勾一下就走；开关写进当前聊天并**一直写回原书**（稍停一下合并保存）。
- 没绑到当前角色的书可在面板底部「管理其他世界书」里分类、编辑，不会进弹窗，也不自动接管。
- 旧版「整本开关」的书自动改成按条目分类，备份和原有设置接过来。

## 状态同步规则

开关立即写入当前聊天的 `chatMetadata.tavern_ruined_me.slots.world`，调用酒馆的 `saveMetadata()` 保存；原书写入共用串行队列，没变化不保存。世界书配置、分组、首次修改备份和最后核对的原书状态存于扩展设置，不包含其它聊天的选择。

1. 新聊天、第一次升级且尚无原书核对记录、角色/全局绑定或聊天绑定世界书变化时，以酒馆当前实际开关为起点，不回放旧快照。旧聊天的其它 slots 不动。
2. 切回已记录聊天时，先读原书，与插件最后核对/写入的状态比较。原书没被外部改动的条目恢复该聊天的选择；检测到外部变化的条目采用新实际状态，只更新当前聊天，不修改其它聊天的元数据。外部启用条目时会解除当前书的总关闭，保证新状态生效。
3. 开场白/其它扩展触发原书更新或绑定更新时重新核对。生成前也检查 `WORLDINFO_ENTRIES_LOADED` 的实际条目；只处理本面板范围内的书。没有完成聊天载入前，不套用上一窗的选择。
4. 异步读书、排队保存前核对聊天 ID、角色、群组、元数据对象、绑定和切换序号。已发出的保存请求不能撤回，但共用队列保证下一聊天等它结束后重新核对；尚未发出的旧任务丢弃。
5. 只能识别接口中可观察到的状态变化：其它扩展如果重复写入完全相同的值，不能判断它是否有新的意图；多个浏览器同时改同一本原书也没有服务端原子锁。不会声称能识别这些不可观察的情况。

原书首次修改前整本备份；卡片底部点「恢复原书」，二次确认后恢复完整备份，并暂停自动接管。切聊天不会重新覆盖恢复结果；再次手动拨动这本书的开关才重新接管。备份只保留第一份，不随日后修改替换。

原生世界书页面的条目开关和灰显随当前聊天更新，显示「聊天配置 · 会同步到原书」。原生编辑器仍可操作，其实际修改会被下一次核对采用。

## 接口依据

核对 SillyTavern `release` 的公开源码（2026-11-08）：

- [world-info.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)：`selected_world_info`、`world_info.charLore[].extraBooks`、`getCharacterLore`、`WORLDINFO_UPDATED`、`WORLDINFO_SETTINGS_UPDATED`、`WORLDINFO_ENTRIES_LOADED`。
- [utils.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/utils.js)：`getCharaFilename` 去掉头像文件名的最后一个扩展名。
- [st-context.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/st-context.js)：角色/群组/聊天 ID、`chatMetadata` 和 `saveMetadata`。

按要求只列角色绑定和全局绑定；单独的聊天绑定书、用户人设书不会因此额外出现在面板。聊天绑定书名仍参与变更检测，防止换开场白时旧配置抢回状态。

## 开发与验证

原生 JS 模块，无 npm 依赖、无打包构建步骤。纯逻辑：`node --test tests/core.test.mjs`。
DOM 测试使用工作间已有的仓库外 jsdom：

```sh
NODE_PATH=/tmp/jsd/node_modules node --test tests/*.test.mjs
node --input-type=module --check < index.js
node --check src/core.mjs
node --check src/ui.mjs
```

24 项测试覆盖实际绑定、聊天隔离、外部更新、异步换窗和连续拨动、编辑冲突、保存反馈、删除确认、备份恢复和原生面板重建。容器没有浏览器，**没截图，也没有真实酒馆验收**。手机请重点验收：390×844 浅/深色、长书名和长组名、删除旁三角、编辑弹窗键盘、分组保存反馈、未分组开关、两个聊天来回切换，以及不同开场白/其它扩展自动换书。
